FlareChain — Project Summary

STATUS: Working prototype using public data, running on a public test blockchain network. Not deployed, not production-ready, and not in use by any real operator, regulator, or registry.

PROBLEM
Emissions and carbon-credit-relevant data — such as gas flaring volumes reported from oil and gas sites — is typically submitted into spreadsheets, registries, or company reports with no independent way to later prove it hasn't been altered. A number can be revised after the fact for legitimate reasons, or quietly changed to understate emissions or inflate a credit claim, and from the outside there is usually no way to tell which happened. This lack of a tamper-evidence layer is a real weak point underneath carbon market trust — and it applies directly to a country like Nigeria, one of the world's largest sources of gas flaring, where flaring data is publicly tracked but not independently verifiable over time.

SOLUTION
FlareChain adds a tamper-evidence layer on top of existing flaring data reporting, without trying to replace how the data is measured. For each reported record, FlareChain computes a cryptographic hash (SHA-256) of its exact contents and anchors that hash on a public blockchain, using the blockchain's own timestamp as an independent record of when that exact version of the data existed. Anyone can later re-hash the record they currently hold and compare it to the anchored hash: a match proves the data is unchanged since reporting; a mismatch proves it was altered. This makes reported data tamper-evident — not tamper-proof, and not automatically accurate — but it means any change after the fact becomes instantly and publicly detectable, without requiring trust in whoever currently holds the data.

CURRENT STAGE: PROTOTYPE
The current build demonstrates the full mechanism end-to-end at small scale: a data-acquisition pipeline pulls public flaring volume data for Nigeria from the World Bank's Global Flaring and Methane Reduction (GFMR) Partnership; a command-line tool hashes and anchors a single record on the Polygon Amoy test network (a free, public, non-production blockchain); a second tool and a small web dashboard re-verify a record against its on-chain anchor on demand. This is a single-record demonstration, not an automated pipeline processing a full dataset, and it runs on a test network with no real economic security guarantees. The underlying data is public satellite-derived flaring estimates, not direct operator or regulator submissions, and the prototype does not yet distinguish Nigeria's legally designated "marginal fields" from other flaring sites — that would require a separate cross-reference against Nigeria's regulatory records that hasn't been built. No organization — including Nigeria's upstream regulator (NUPRC) or any oil operator — has reviewed, endorsed, or adopted this prototype.

WHAT EXPANSION WOULD LOOK LIKE WITH FUNDING OR PARTNERSHIP
With support, the next stage would involve: moving from a test network to a production-grade blockchain deployment with real key management and cost planning; building an automated pipeline that anchors an entire dataset on a schedule rather than one record at a time by hand; validating flaring/emissions figures against a more authoritative source than satellite estimates, ideally direct operator or regulator submissions; building the marginal-field cross-reference against NUPRC's published records; and engaging directly with a data owner, regulator, or carbon registry to test whether — and how — a tamper-evidence layer like this could fit into an existing reporting or verification workflow. None of this is underway yet; it is the concrete next step this prototype was built to justify.
